# داشبورد مورین‌داک {Morindok}

داشبورد حرفه‌ای Dash برای آنالیز قدرت خریدار/فروشنده، چرخش سرمایه بین ۳۰ ارز،
آنالیز عمق حجم، و سیستم سیگنال‌دهی معاملاتی روی داده‌ی زنده‌ی **Bybit**.

## ساختار پروژه
```
app.py               رابط کاربری Dash (سه تب: آنالیز / سیگنال‌ها / وین‌ریت)
bybit_engine.py       لایه‌ی داده: REST kline، ticker، WebSocket تیک‌به‌تیک،
                      محاسبه‌ی cfield2، چرخش سرمایه، آنالیز حجم
signals_engine.py     موتور سیگنال، مدیریت SL/TP، آمار وین‌ریت (SQLite)
requirements.txt      وابستگی‌ها
```

## نصب و اجرا
```bash
pip install -r requirements.txt
python app.py
```
سپس مرورگر را روی `http://127.0.0.1:8050` باز کنید.

## نکات فنی مهم

### ۱) فرمول قدرت خریدار/فروشنده (cfield2)
دقیقاً طبق فرمول ارسالی شما پیاده‌سازی شده:
```
cfield2 = round( (Buy_I_Volume/Buy_CountI) / (Sell_I_Volume/Sell_CountI) * 10 ) / 10
```
این فرمول به داده‌ی **تیک‌به‌تیک معاملات** نیاز دارد (حجم و تعداد هر معامله‌ی
خرید/فروش به‌تفکیک)، و این داده در Kline معمولی Bybit REST وجود ندارد.
به همین دلیل برنامه از WebSocket عمومی Bybit (`publicTrade`) استریم زنده‌ی
معاملات را می‌گیرد و در حافظه بافر می‌کند. **هرچه برنامه بیشتر روشن بماند،
عمق تاریخچه‌ی دقیق قدرت بیشتر می‌شود.**

تا زمانی‌که داده‌ی زنده‌ی کافی جمع نشده، از یک روش تخمینی جایگزین (بر اساس
موقعیت بسته‌شدن کندل نسبت به بازه‌ی high/low) استفاده می‌شود که در رابط
کاربری با برچسب «تخمینی» از حالت «دقیق» متمایز شده است.

### ۲) چرخش سرمایه بین ۳۰ ارز
برای هر یک از ۳۰ ارز، جریان نقدی خالص (خرید منهای فروش به دلار) در بازه‌های
۵ دقیقه‌ای از استریم زنده محاسبه و با جریان ارز انتخابی هم‌بسته‌سنجی
(cross-correlation با تاخیر ۰ تا ۳ کندل) می‌شود. این یک **مدل همبستگی** است
برای شناسایی ارزهایی که همزمان یا اندکی زودتر ورود/خروج پول مشابه داشته‌اند؛
رابطه‌ی علّی قطعی را تضمین نمی‌کند.

### ۳) آنالیز عمق مشکوک بودن حجم
بر اساس z-score حجم نسبت به میانگین متحرک ۲۰ کندل + نسبت حجم به میزان
حرکت قیمت. حجم بسیار بالا همراه با حرکت قیمتی ناچیز به‌عنوان «مشکوک»
(احتمال دستکاری/شست‌وشوی حجم) علامت‌گذاری می‌شود.

### ۴) سیستم سیگنال
نمره‌ی ترکیبی قدرت روی همه‌ی تایم‌فریم‌ها (۱، ۵، ۱۵، ۳۰ دقیقه، ۱، ۴ ساعته و
روزانه) با وزن‌دهی بیشتر به تایم‌فریم بالاتر محاسبه می‌شود (کاسکید بالا به
پایین). حد ضرر/سود بر اساس ATR(14) روی تایم‌فریم ۱ ساعته و اهرم پیشنهادی
بر اساس درصد نوسان تعیین می‌شود. سیگنال تا برخورد قیمت با SL یا TP باز
می‌ماند (بررسی هر ۲۰ ثانیه) و نتیجه در SQLite برای محاسبه‌ی وین‌ریت ذخیره
می‌شود.

## محدودیت‌های شناخته‌شده / پیشنهاد توسعه
- محیط تست من (Claude sandbox) دسترسی شبکه به `api.bybit.com` نداشت؛ کد
  دقیقاً بر اساس مستندات رسمی Bybit v5 نوشته شده اما توصیه می‌کنم لاگ اولین
  اجرا را چک کنید تا از صحت اتصال WebSocket مطمئن شوید.
- برای دقت بالاتر مدل چرخش سرمایه، می‌توان به‌جای همبستگی ساده از
  Granger Causality یا مدل‌های یادگیری ماشین استفاده کرد.
- در صورت نیاز به اجرای مداوم ۲۴ ساعته، پیشنهاد می‌شود پروسه را با
  systemd/pm2 و ری‌استارت خودکار مدیریت کنید تا در صورت قطعی وب‌سوکت،
  بافر معاملات به‌سرعت بازسازی شود.
